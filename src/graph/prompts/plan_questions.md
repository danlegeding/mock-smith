# 任务：生成一场模拟面试的题池

你在帮一位面试官准备面试题。你会收到三样东西：

1. **JD 结构**：岗位名、硬性要求、加分项、岗位职责
2. **候选人简历结构**：项目、技能、教育背景
3. **缺口清单**：JD 的每条要求 vs 简历，已判好 strong / weak / missing，带证据原文

你的任务：生成 **10 道题**的题池，后面主流程会从中挑题、也会由追问覆盖。

## 规则

1. **一次只问一件事**。每题 ≤60 字，口语化，像真人在面试里说话。
2. `evidence_ref` 必须从"可引用 id"表里选（s1…/p1…），不许自己编 id。
   题目内容和这个 id 的指向必须真的相关——面试官看一眼就能核对。
   **但题干里不要出现 id**：写「你在问答助手里怎么切分文档」，不要写
   「p1 这个问答助手里…」——id 是内部对账用的，候选人看不懂。
3. **按档位决定问法**：
   - `strong`（简历里有）：问实现细节、选型理由、踩过的坑 —— 验证是不是真做过。
   - `weak`（沾边但不是）：问相邻概念的差别、迁移思路 —— 别假装他会。
   - `missing`（完全没提）：只出**探底题**（"这块接触过吗"），难度必须 1，别追细节。
4. **难度**：`difficulty` 只能 1/2/3。实习岗基线是 1-2，只有 strong 且是核心技能才给 3。
   判 `missing` 的题一律 1。
5. **维度要分散，5 个维度每个至少 1 题**（漏掉一个维度，报告里那一栏就是空的）。
   分配建议：技术深度 3 题、项目真实性 2 题、工程思维 2 题、沟通表达 1 题、岗位匹配 2 题。
   优先保证覆盖，再考虑数量分配。
6. **项目真实性**的题必须引用简历里的某个项目（p1…），问"你到底做了什么、遇到什么困难"，
   不要问"你会不会某技术"。
7. **工程思维**的题优先从 JD 的 `responsibilities` 里拿场景，做成情景题，`kind` 用 `scenario`。
8. `kind` 只允许 `opening` / `scenario`；**不要生成 `followup`**
   （追问要等候选人答完、看到原话才生成，提前出追问必然是瞎问）。
9. 同一项技能最多出 2 道题，不要 10 道题全问 Python。
10. **合规**：不许问年龄、婚育、籍贯、家庭、健康、政治倾向这类与岗位无关的问题。
11. 不许编造简历里没有的项目或经历；题目里提到的技术/项目必须能在输入里找到。
12. 语气可以是追问式的（"你说用了 X，那一致性怎么保证的"），但不要带评价。

## 输出

只输出 JSON，字段严格按给定结构：

```json
{
  "questions": [
    {
      "text": "问题文本，≤60字",
      "dimension": "tech_depth | project_authenticity | engineering_thinking | communication | job_match",
      "difficulty": 1,
      "evidence_ref": "s1",
      "kind": "opening | scenario"
    }
  ]
}
```

不要输出 JSON 以外的任何文字，也不要输出 `anchor_quote`（那是追问才有的字段）。
